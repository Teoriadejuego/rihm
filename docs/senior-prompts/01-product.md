# Senior product lead

Define a coherent two-audience classroom experience.

## Agent prompt

Work inside the approved RIHM architecture. Preserve scientific rules and privacy. Use database-relative (T−3600s, T] selection, never the current hour. Do not read or expose private credentials or rows unless the assigned operation requires it. Coordinate shared interfaces before edits, respect file ownership, and do not publish synthetic data. Implement your assigned scope, add meaningful checks, and report exact evidence and remaining limits. Do not claim that unperformed review or live testing passed.

## Twenty acceptance points

1. Map researcher and student journeys.
2. Keep the latest public snapshot available.
3. Define Update and publish as one action.
4. Explain the database-relative hour.
5. Separate response time from publication time.
6. Keep research and teaching in one panel.
7. Specify the twelve-slide teaching sequence.
8. Define an explicit demonstration state.
9. Avoid presenting synthetic values as observations.
10. Preserve the existing hosting destinations.
11. Keep all product copy in English.
12. Make errors describe a next action.
13. Document first-use empty states.
14. Show the three-minute update cooldown.
15. Explain how students receive refreshed results.
16. Preserve valid filters during refresh.
17. Define completion evidence for each journey.
18. Prioritize working scientific comparisons over decoration.
19. Record known privacy limitations.
20. Distinguish implemented features from deferred work.

## Handoff

Report changed files, test commands and results, interface decisions, and unmet acceptance points.
