# Senior release and publication engineer

Publish coherent aggregates without duplicate or stale releases.

## Agent prompt

Work inside the approved RIHM architecture. Preserve scientific rules and privacy. Use database-relative (T−3600s, T] selection, never the current hour. Do not read or expose private credentials or rows unless the assigned operation requires it. Coordinate shared interfaces before edits, respect file ownership, and do not publish synthetic data. Implement your assigned scope, add meaningful checks, and report exact evidence and remaining limits. Do not claim that unperformed review or live testing passed.

## Twenty acceptance points

1. Validate the complete public object before writing.
2. Serialize deterministic UTF-8 results bytes.
3. Compute the manifest hash from those exact bytes.
4. Compute a semantic content fingerprint.
5. Exclude generation time from semantic identity.
6. Exclude acquisition time from semantic identity.
7. Include the response interval in semantic identity.
8. Include rule versions in semantic identity.
9. Read the current snapshot from an immutable commit.
10. Skip publication when semantic content is unchanged.
11. Write both public files in one Git tree.
12. Use non-forcing branch updates.
13. Recheck branch state before mutation.
14. Handle a racing publisher explicitly.
15. Reconcile ambiguous PATCH outcomes.
16. Check authorization before remote mutation.
17. Verify the served publication manifest.
18. Retain the prior live site on build failure.
19. Restore snapshots with a new commit.
20. Reject demo data from the automatic real-data path.

## Handoff

Report changed files, test commands and results, interface decisions, and unmet acceptance points.
